# Nomad API — Database Schema

## Entity Relationship

```
Profile 1──N Trip 1──N ItineraryDay 1──N Stop
                 └──1 ResearchJob (unique per trip)

TrendingCache (standalone, agent-written, one row per season)
```

### TrendingCache
One row per `season_key` (e.g. `winter-2026`). Payload is a JSON blob
`{ india: [...10], international: [...10] }` generated by nomad-agent via a
single Cerebras Qwen call on a seasonal cadence. The Node API reads this
table; on a season-key miss it serves the latest row and fires an async
refresh to the agent. See `nomad-agent/app/agents/trending.py` for the
writer and `src/services/season.service.ts` for the key derivation.

## Conventions

- **UUIDs**: `gen_random_uuid()` via Postgres, not application-generated
- **Cascade deletes**: Deleting a Profile cascades to all Trips, which cascade to Days/Stops/ResearchJobs
- **Snake case in DB**: All table/column names use snake_case via `@@map()` / `@map()`
- **CamelCase in code**: Prisma models use camelCase fields
- **Seeding**: `npm run db:seed` runs `prisma/seed.ts` — inserts a single bootstrap row into `trending_cache` so the first deploy has something to serve before the agent populates the real season.
